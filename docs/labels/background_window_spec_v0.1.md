# Background Window Specification v0.1

**Created:** 2026-07-09
**Applies to:** `labels/background_windows_v0.1/`
**Reference labels:** BOAS PSG `stage_hum`
**Model training performed:** No

## 1. Purpose

This specification defines non-transition background windows for later REM-to-Wake boundary-detection experiments.

The technical issue is label contamination. A background window should not overlap the uncertainty interval around a REM-to-Wake or Wake-to-REM boundary, otherwise the project could train or evaluate a detector on ambiguous examples.

## 2. Window Geometry

- Window length: 240 seconds.
- Window center: adjacent PSG epoch boundary.
- Sampling rate for sample-index mapping: 256 Hz.
- Expected window sample count: 61,440 samples.
- Positive transition uncertainty: +/-15 seconds around the nominal boundary.
- Background exclusion radius around any REM/Wake boundary: 135 seconds.

The 135-second radius equals the 120-second half-window plus the 15-second boundary uncertainty interval.

## 3. Inclusion Rule

A background candidate is eligible only if:

1. the 240-second window is fully covered by PSG event labels;
2. the center is not a direct REM-to-Wake or Wake-to-REM boundary;
3. the window does not intersect any REM/Wake boundary uncertainty interval;
4. all involved PSG epochs are 30 seconds;
5. no involved PSG epoch has missing `stage_hum`;
6. no involved PSG epoch is PSG disconnection.

## 4. Background Tiers

| Tier | Meaning | Intended use |
|---|---|---|
| `strict_same_stage_window` | All PSG epochs in the window have the same stage | Conservative negative examples and quality review |
| `nontarget_window_no_remwake_nearby` | The window may contain other stage changes but no nearby REM/Wake boundary | Later robustness/background diversity review |

## 5. Current Result

The v0.1 build found:

- 119,967 possible adjacent-epoch centers;
- 115,275 eligible background centers;
- 83,688 strict same-stage background centers;
- 31,587 non-target background centers with no nearby REM/Wake boundary;
- 4,302 deterministic review rows written to Git.

The full eligible pool is summarized but not written as a large Git artifact. It can be regenerated by `scripts/build_background_windows_v0_1.py`.

## 6. Decision

Use this rule set for the label/preprocessing gate. Do not create final train/validation/test splits until background sampling and signal-quality flags are reviewed together.
